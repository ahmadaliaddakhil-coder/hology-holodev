# TASK 4.3-4.7 Integration Summary

## TASK 4.3: Location and BMKG evidence

Existing BIG boundary lookup and BMKG `adm4` verification remain separate. The API exposes `POST /api/locations/resolve` and deliberately returns `mappingVerified: false` because BIG attributes are not silently treated as BMKG `adm4`.

`POST /api/decision-cases/:decisionCaseId/bmkg/refresh` uses the existing `BmkgAdapter`, including timeout, limited retry, normalization warnings, and process-local cached fallback. The canonical evidence is persisted with `source=BMKG`, delivery metadata, freshness, and mock provenance.

`POST /api/decision-cases/:decisionCaseId/field-pulse` persists local observations. `unknown` is accepted as valid evidence.

## TASK 4.4: Deterministic reasoning

`WaterReasoningEngine` implements the HOL-87 water v0.2 boundary:

- complete BMKG plus complete Field Pulse produces `context_available` and medium basis strength;
- partial or unknown Field Pulse produces `needs_verification` and low basis strength;
- missing BMKG or Field Pulse produces `insufficient_evidence` and abstention;
- output is alternatives-only and never contains a recommended option;
- no agronomic threshold or risk score is invented.

The engine returns explanation contract fields with evidence references and limitation codes.

## TASK 4.5: Assessment and trusted review

`POST /api/decision-cases/:decisionCaseId/assess` persists a new assessment version and action options, superseding the previous active assessment. Review repositories and endpoints support review requests, submissions, status, and comments.

## TASK 4.6: Human decision record

Decision creation is explicit and idempotent for repeated identical requests. A different second decision returns `409`; existing records are never overwritten. Optional evidence IDs are linked through `decision_record_evidence`, and the case is closed after the record is created.

## TASK 4.7: Deterministic Decision Brief

Decision briefs and share text are generated by `formatDecisionBrief`. The formatter uses persisted case, assessment, and decision fields only; it does not call an LLM or accept free-form generated content from the client.

## Validation

- `npm run build`
- `npm test`

Both commands include the BMKG adapter tests and deterministic reasoning tests.
